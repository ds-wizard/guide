## Decisions reflected in the guide

- No user-facing workspaces: no workspace selector, membership, role, library, settings, branding or access instructions. The `workspace` property is mentioned only as a field of the shared raw document context
- Excluded FW-only UI: Analytics, Audit Log, login automations, project CSV import, Data Source management, SAML settings, Connected AIs and commercial plans
- DSW routes expose direct Create User, not the FW invite/import workflow. Roles remain instance-wide; their permission matrix comes from WizardRolePermission.allGroups
- Registry translation import is available in OS. FW official push/automatic-update rules were not imported into DSW instructions
- Registry connection is an account API key, content identifiers use a dot and versions are separate. Context 19.0 and KM metamodel 20 verified against OS backend constants
- Backend hosting configuration `multiTenancy` is separate from user-facing workspaces. Client is served at the root with API base `/api`; updated old `/wizard`, `window.dsw`, favicon and Bootstrap customization instructions
- Retained established URLs targeted by Dsw.Data.GuideLinks. New user groups, translations and split settings pages are linked through the toctrees
- Native Sphinx TODOs are the single visible screenshot placeholder mechanism; screenshots will be captured only when an environment is supplied. No screenshot environment was accessed or mutated

## Specification/implementation differences and limits

- WEP 41's newer text proposes MCP for OS, while the current OS client has no consent/Connected AI routes and the user explicitly excludes OS MCP. No MCP workflow is claimed in this guide; confirm scope with developers if that decision changes
- Shared backend has workspace schema/handlers, but DSW's client has no workspace plane. Schema presence is not treated as a DSW feature
- No browser/app acceptance run against a DSW 5.0 environment; none is supplied yet. This is documentation/source verification, not a claim that all flows have passed runtime testing
- Existing 4.x upgrade sections are historical. No production release, Read the Docs settings, Notion content or frontend/backend source changed
